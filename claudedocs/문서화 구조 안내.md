## 개요

### 목적

이 문서는 프로젝트의 `docs/` 디렉토리 구조와 각 문서의 역할을 설명하여:
- **신규 개발자**가 프로젝트 문서를 빠르게 찾을 수 있도록 안내
- **기존 개발자**가 문서를 어디에 작성해야 할지 명확히 제시
- **일관성** 있는 문서화 구조 유지

### 문서화 원칙

1. **중앙 집중화:** 모든 프로젝트 문서는 `docs/` 디렉토리에 통합
2. **분류 체계:** 주제별로 하위 디렉토리에 분류
3. **언어:** 프로젝트 공식 언어 (한국어/영어) 사용
4. **버전 관리:** 중요한 변경사항은 문서 상단에 버전 정보 명시

```
    └── docs/reference/
```

#### Step 3: 문서 검토

1. **내용 검토:**
   - [ ] 정보가 정확한가?
   - [ ] 최신 상태인가?
   - [ ] 이해하기 쉬운가?

2. **형식 검토:**
   - [ ] 마크다운 형식이 올바른가?
   - [ ] 코드 예시가 실행 가능한가?


### 2. 기존 문서 수정

#### 수정 전 체크리스트

- [ ] 문서의 **버전** 정보 확인
- [ ] **마지막 수정** 날짜 업데이트
- [ ] **변경 사항**을 버전 history에 기록

#### 수정 예시

```markdown
<!-- 변경 전 -->

**작성일:** 2026-01-01

---

**마지막 수정:** 2026-01-15

---

- v1.0.0 (2026-01-01): 초기 버전
```

## FAQ

### Q1: 문서는 어디에 작성해야 하나요?

**A:** 문서의 유형에 따라 적절한 하위 디렉토리에 작성하세요:
- 아키텍처: `docs/architecture/`
- API: `docs/api/`
- 가이드: `docs/guides/`
- 개발: `docs/development/`

### Q2: 코드 변경 시 문서도 업데이트해야 하나요?

**A:** 네, 코드와 문서는 함께 업데이트해야 합니다. PR 템플릿에 "문서 변경" 항목을 포함하여 확인하세요.

### Q3: 오래된 문서는 어떻게 처리하나요?

**A:**
1. 문서 상단에 "오래됨" 경고 추가
2. 가능한 한 빨리 업데이트
3. 더 이상 필요 없으면 삭제 팀원들과 협의 후 삭제

### Q4: 문서 작성 우선순위는?

**A:**
1. **L1 (필수):** 공개 API, 복잡한 로직, 아키텍처
2. **L2 (권장):** 컴포넌트, 가이드, 튜토리얼
3. **L3 (선택):** 간단한 함수, 일반적인 정보
