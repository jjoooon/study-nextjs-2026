## 일반 원칙

### 기본 규칙

- **영어 사용**: 모든 이름은 영어로 작성
- **의미 중심**: 이름은 용도를 명확하게 설명해야 함
- **일관성**: 동일한 유형의 요소는 동일한 패턴 사용
- **줄임말 지양**: 명확하지 않은 줄임말 사용 지양 (`btn` → `button`, `msg` → `message`)
- **카멜케이스 기본**: 기본적으로 camelCase 사용

### 예외

- **상수**: `SCREAMING_SNAKE_CASE`
- **타입/인터페이스**: `PascalCase`
- **파일명**: `camelCase` (컴포넌트 제외)

## 파일 네이밍

### 1. 컴포넌트 파일

**규칙**: `PascalCase.tsx`

**예시**:
```
ProductForm.tsx
ProductList.tsx
DashboardStats.tsx
ErrorBoundary.tsx
```

**이유**:
- React 컴포넌트와 파일명을 일치시켜 가독성 향상
- import 시 자동완성 용이

### 2. 유틸리티/헬퍼 파일

**규칙**: `camelCase.ts`

**예시**:
```
error.ts
logger.ts
dateUtils.ts
zodHelpers.ts
```

**이유**:
- 함수나 변수명과 일관성 유지
- 유틸리티 성격 명확히 구분

### 3. 훅 파일

**규칙**: `use[FeatureName].ts`

**예시**:
```
useProducts.ts
useProduct.ts
useDashboard.ts
useProductsURLState.ts
```

**이유**:
- React Hook 규칙 (`use` 접두사) 준수
- Custom Hook임을 명확히 식별

### 4. 타입 정의 파일

**규칙**: `[domain].[category].ts`

**예시**:
```
products/types/api.ts
products/types/store.ts
products/types/ui.ts
```

**이유**:
- 기능별 타입 분리로 관리 용이성 확보
- import 경로 명확화

### 5. Store/Slice 파일

**규칙**: `[feature][SliceType]Slice.ts` 또는 `[feature]Selectors.ts`

**예시**:
```
productsUISlice.ts
authSlice.ts
dashboardSlice.ts
productsSelectors.ts
authSelectors.ts
```

**이유**:
- Redux Toolkit 패턴 준수
- Slice와 Selector 파일 구분

## 변수 및 함수 네이밍

### 1. 변수 (Variables)

**규칙**: `camelCase`

**예시**:
```typescript
// ✅ 좋은 예
const productList = [];
const totalProducts = 0;
const isLoading = false;

// ❌ 나쁜 예
const products_list = [];
const totalproducts = 0;
const flag = false;
```

### 2. 상수 (Constants)

**규칙**: `SCREAMING_SNAKE_CASE`

**예시**:
```typescript
// ✅ 좋은 예
const MAX_RETRY_COUNT = 3;
const DEFAULT_PAGE_SIZE = 10;
const API_BASE_URL = 'https://api.example.com';

// ❌ 나쁜 예
const maxRetryCount = 3;
const default_page_size = 10;
```

### 3. 함수 (Functions)

**규칙**: `camelCase`, 동사로 시작

**예시**:
```typescript
// ✅ 좋은 예
function getErrorMessage() {}
function handleFilterChange() {}
function validateFormData() {}
function toggleProductSelection() {}

// ❌ 나쁜 예
function errorMessage() {} // 명확하지 않음
function filter() {} // 동어반복
function validation() {} // 명사 사용
```

### 4. 이벤트 핸들러

**규칙**: `handle[EventName]`

**예시**:
```typescript
// ✅ 좋은 예
const handleSubmit = () => {}
const handleFilterChange = () => {}
const handleClick = () => {}
const handleProductClick = () => {}

// ❌ 나쁜 예
const onSubmit = () => {} // 혼동 가능
const changeFilter = () {} // 핸들러임이 명확하지 않음
```

### 5. 불리언 변수

**규칙**: `is/has/should/can` 접두사

**예시**:
```typescript
// ✅ 좋은 예
const isLoading = true;
const hasError = false;
const shouldUpdate = true;
const canEdit = false;

// ❌ 나쁜 예
const loading = true;
const error = false;
const update = true;
```

## 컴포넌트 네이밍

### 1. 컴포넌트 이름

**규칙**: `PascalCase`

**예시**:
```typescript
// ✅ 좋은 예
export default function ProductsPage() {}
export default function ProductForm() {}
export default function DashboardStats() {}

// ❌ 나쁜 예
export default function productsPage() {}
export default function product_form() {}
```

### 2. 컴포넌트 Props 인터페이스

**규칙**: `[ComponentName]Props`

**예시**:
```typescript
// ✅ 좋은 예
interface ProductFormProps {
  initialData?: Product;
  mode: 'create' | 'update';
}

interface ProductListProps {
  products: Product[];
  onProductClick: (product: Product) => void;
}

// ❌ 나쁜 예
interface Props {} // 너무 일반적
interface ProductFormProperties {} // 너무 김
```

### 3. HOC/Wrapper 컴포넌트

**규칙**: `with[FeatureName]` 또는 `[FeatureName]Wrapper`

**예시**:
```typescript
// ✅ 좋은 예
export default function withAuth(Component) {}
export default function PerformanceMonitorWrapper() {}

// ❌ 나쁜 예
export default function Auth() {}
export default function Wrapper() {}
```

### 4. 컨테이너 vs 프레젠테이셔널

**규칙**:
- **프레젠테이셔널**: `[FeatureName][ComponentType]`
- **컨테이너**: `[FeatureName]Page` 또는 `[FeatureName]Container`

**예시**:
```typescript
// 프레젠테이셔널 컴포넌트
ProductForm.tsx
ProductList.tsx
ProductFilters.tsx

// 컨테이너/페이지 컴포넌트
ProductsPage.tsx
DashboardPage.tsx
```

## �입 및 인터페이스 네이밍

### 1. 인터페이스 (Interfaces)

**규칙**: `PascalCase`

**예시**:
```typescript
// ✅ 좋은 예
interface Product {}
interface CreateProductInput {}
interface ProductsListResponse {}

// ❌ 나쁜 예
interface product {}
interface IProduct {} // I 접두사 지양
interface ProductInterface {} // 불필요한 접미사
```

### 2. 타입 별칭 (Type Aliases)

**규칙**: `PascalCase`

**예시**:
```typescript
// ✅ 좋은 예
type ProductStatus = 'active' | 'inactive' | 'archived';
type ViewMode = 'table' | 'grid';
type ProductsUIState = {
  selectedProducts: number[];
  viewMode: ViewMode;
};

// ❌ 나쁜 예
type productStatus = 'active' | 'inactive' | 'archived';
type TProductStatus = 'active' | 'inactive' | 'archived'; // T 접두사 지양
```

### 3. 제네릭 타입

**규칙**: `T` 또는 의미있는 `PascalCase`

**예시**:
```typescript
// ✅ 좋은 예
function identity<T>(value: T): T { }
interface ApiResponse<Data> {
  data: Data;
}
interface PaginatedResponse<Item> {
  items: Item[];
  total: number;
}

// ❌ 나쁜 예
function identity<Value>(value: Value): Value { } // 너무 일반적
```

### 4. Enum

**규칙**: `PascalCase` (Enum), `PascalCase` (멤버)

**예시**:
```typescript
// ✅ 좋은 예
enum ProductStatus {
  Active = 'active',
  Inactive = 'inactive',
  Archived = 'archived',
}

// ❌ 나쁜 예
enum productStatus {}
enum ProductStatus {
  ACTIVE = 'active', // SCREAMING_SNAKE_CASE는 상수에 사용
}
```

## 상수 네이밍

### 1. 전역 상수

**규칙**: `SCREAMING_SNAKE_CASE`

**예시**:
```typescript
// ✅ 좋은 예
const MAX_UPLOAD_SIZE = 5 * 1024 * 1024; // 5MB
const API_TIMEOUT = 30000; // 30초
const DEFAULT_PAGE_SIZE = 10;

// ❌ 나쁜 예
const maxUploadSize = 5 * 1024 * 1024;
const api_timeout = 30000;
```

### 2. 객체 내 상수

**규칙**: `SCREAMING_SNAKE_CASE` (계층적 상수 구조)

**예시**:
```typescript
// ✅ 좋은 예 - 관련 상수를 객체로 묶고 SCREAMING_SNAKE_CASE 사용
export const API = {
  BASE_URL: '/api',
  TIMEOUT: 10000,
  RETRY_COUNT: 3,
  STATUS: {
    OK: 200,
    NOT_FOUND: 404,
  },
} as const;

export const PRODUCT_STATUS = {
  ACTIVE: 'active',
  INACTIVE: 'inactive',
  ARCHIVED: 'archived',
} as const;

// ❌ 나쁜 예 - camelCase 사용
const config = {
  maxFileSize: 5 * 1024 * 1024,
  apiTimeout: 30000,
};

// ❌ 나쁜 예 - 흩어진 정의
export const ACTIVE = 'active';
export const INACTIVE = 'inactive';
export const ARCHIVED = 'archived';
```

**이유**:
- 상수임을 명확하게 식별
- 관련 상수를 객체로 그룹화하여 관리 용이
- `as const`로 불변성 보장 및 타입 추론 지원

## 폴더 구조

### 1. 기본 규칙

**규칙**: `kebab-case` 또는 `camelCase`

**예시**:
```
src/
├── app/                    # Next.js App Router
├── features/               # 기능별 모듈
│   ├── auth/
│   ├── dashboard/
│   └── products/
├── shared/                 # 공유 코드
│   ├── components/
│   ├── lib/
│   └── utils/
└── store/                  # 전역 상태 관리
```

### 2. 기능별 폴더 구조

**규칙**: `kebab-case` (기능명)

**예시**:
```
features/
├── auth/
│   ├── components/
│   ├── hooks/
│   ├── store/
│   ├── types/
│   └── utils/
├── dashboard/
│   └── ...
└── products/
    └── ...
```

### 3. 공유 폴더 구조

**예시**:
```
shared/
├── components/
│   ├── common/              # 일반 컴포넌트
│   ├── layout/              # 레이아웃 컴포넌트
│   └── ui/                  # UI 컴포넌트 (shadcn/ui)
├── lib/
│   ├── axios/
│   └── shadcn/
└── utils/
    ├── date/
    ├── url/
    └── validation/
```

## 특별한 경우

### 1. Redux 관련

**Slice**:
```typescript
// 파일명: productsUISlice.ts
export const productsSlice = createSlice({ ... });
export default productsSlice.reducer;
```

**Selector**:
```typescript
// 파일명: productsSelectors.ts
export const selectSelectedProducts = (state: RootState) => ...;
export const selectViewMode = (state: RootState) => ...;
```

**Action Creator**:
```typescript
// ✅ 좋은 예
toggleProductSelection
selectAllProducts
clearProductSelection
setViewMode

// ❌ 나쁜 예
toggleSelection // 명확하지 않음
select // 동어반복
```

### 2. RTK Query API

**규칙**: `use[ActionName][Query/Mutation]`

**예시**:
```typescript
// ✅ 좋은 예
const { data } = useGetProductsQuery();
const [createProduct, { isLoading }] = useCreateProductMutation();

// ❌ 나쁜 예
const { data } = useProductsQuery();
const [create] = useCreateMutation();
```

### 3. Zod 스키마

**규칙**: `[entity]Schema` 또는 `[action][entity]Schema`

**예시**:
```typescript
// ✅ 좋은 예
const createProductSchema = z.object({ ... });
const updateProductSchema = z.object({ ... });
const productSchema = z.object({ ... });

// ❌ 나쁜 예
const schema = z.object({ ... });
const productValidation = z.object({ ... });
```

### 4. Next.js 파일 규칙

**특별한 파일명**:
```
page.tsx          # 페이지 컴포넌트
layout.tsx        # 레이아웃 컴포넌트
loading.tsx       # 로딩 컴포넌트
error.tsx         # 에러 컴포넌트
not-found.tsx     # 404 컴포넌트
```

**Route Groups**: `(group-name)`
```
(auth)/           # 인증 관련 라우트
(dashboard)/      # 대시보드 라우트
```
